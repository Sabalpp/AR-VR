# Sponsor integration boundaries

Impiricus is the primary challenge narrative: give clinicians a concise, evidence-linked review of assigned rehabilitation activity and patient feedback, suitable for a human-reviewed follow-up conversation. The dashboard shows assignment context, observable measurements, tracking limitations, replay and patient notes together. This is a clinician workflow implementation, not an Impiricus API integration. No Impiricus API endpoint, credential or delivery confirmation is invented. Actual submission/challenge fit requires the team's supplied challenge brief; messaging through an external system requires its documented API and access.

Tiger Data can host the same PostgreSQL schema used locally. Set `DATABASE_URL` to the supplied PostgreSQL connection URI, using the SQLAlchemy `postgresql+psycopg` driver and TLS parameters required by that service. Ordinary PostgreSQL is the supported baseline. No mandatory Timescale extension or unverified hypertable conversion is needed for the small chunk workload.

Gemini is an optional server-side report adapter. Feed persisted metrics and separately labeled patient notes to the model. Gemini returns only an ordered list of allowed fact codes derived from the saved metrics. The server validates that every allowed code appears exactly once and renders all numerical claims itself; no model-generated prose or clinical claim is accepted. Patient notes are snapshotted and attributed separately. The deterministic fallback remains available when keys are absent, requests fail or output is rejected. Model identity/version belongs in each report. [Official structured output documentation](https://ai.google.dev/gemini-api/docs/structured-output).

ElevenLabs voices approved instruction/cue IDs, with repeated phrase caching and playback cooldowns. It does not observe or count movement, and a failed or slow speech request must not block frame processing. Browser audio requires an explicit user gesture. [Official text-to-speech API](https://elevenlabs.io/docs/api-reference/text-to-speech/convert).

Presage is optional and disabled. The team has not verified available developer access or phone-browser/Quest platform support. No vital signs are fabricated, and no Presage success is claimed. Enablement requires verified supported SDK, consent/data-flow design and separate hardware acceptance work.
